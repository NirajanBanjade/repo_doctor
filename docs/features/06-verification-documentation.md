# Feature 06 — Verification & Documentation

## Purpose

After tests have been executed, produce an evidence-based verification report that reconciles observed test results with the stated impact risks, identifies unresolved risks and untested components, proposes improvements to the repository's setup documentation, and generates a pull-request summary the developer can review before submitting.

---

## Functional Requirements

1. Collect all test results, impact run data, environment check results, and Bob agent findings for the current session.
2. Invoke the Verification Agent via Bob to reconcile test outcomes against the stated impact risks and change description.
3. Produce a `VerificationReport` that explicitly states: what passed, what failed, what was not tested, and which risks remain unresolved hypotheses.
4. Propose concrete, diff-formatted improvements to the repository's setup documentation where blockers were found and fixed during Environment Doctor.
5. Generate a draft PR summary including: change description, test evidence, impacted components, unresolved risks, and links to source evidence.
6. Require developer review before the PR summary or documentation patch is considered final — no automatic submission.
7. Persist all report content in the session evidence store.

## Technical Implementation

### Evidence aggregation (`app/services/verification.py`)

Collect and structure:
- All `test_results` for the session's impact run, grouped by `component_id`.
- All `impact_nodes` with their `evidence_status` and depth.
- All `environment_checks` with `status` and any applied fixes.
- All `ImpactAnnotations` hypotheses that were not resolved by test evidence.

### Verification Agent invocation

Pass Bob: structured evidence summary (test outcomes by component, unresolved hypotheses, confirmed edges vs inferred edges, change description).

Validate response against `VerificationReport` schema:
```
components_verified[]:
  - component_id: str
  - status: "passed" | "failed" | "unexecuted" | "no_test"
  - evidence_refs: str[]        # test file:line, graph edge file:line

unresolved_risks[]:
  - hypothesis: str
  - component_id: str
  - reason_unresolved: str

documentation_gaps[]:
  - file: str
  - current_text: str
  - proposed_text: str
  - reason: str

pr_summary: str
```

### Documentation patch generation

For each `documentation_gap` in the Verification Agent output:
1. Locate the referenced file in the working copy.
2. Generate a unified diff using Python's `difflib`.
3. Write to `working_copy/docs/fixes/{filename}.patch`.
4. Never modify the original repository's documentation files directly.

### PR summary

The PR summary is a Markdown document containing:
- Change description (from ImpactScope run).
- Test results table (component, status, evidence link).
- Unresolved risks (labeled as hypotheses).
- Links to relevant graph nodes and test files.
- Note: "This summary was generated by RepoDoc and must be reviewed before submission."

## Acceptance Criteria

1. The `VerificationReport` lists every selected impact node with one of: `passed`, `failed`, `unexecuted`, or `no_test`.
2. The seeded regression is reported as `failed` with the failing test name and assertion as evidence.
3. At least one unresolved risk is listed for any inferred edge that was not covered by a test.
4. The documentation patch correctly addresses the seeded setup blockers fixed during Environment Doctor.
5. The PR summary is human-readable, references specific files and line numbers, and includes the "must be reviewed" disclaimer.
6. No report element claims full safety or complete impact coverage.
7. The developer can view the report and documentation patch before taking any submission action.

---

## Testing Requirements

- Unit test: `VerificationReport` schema validation rejects a report with a component missing `status`.
- Unit test: Documentation patch generator produces a valid unified diff from a known before/after fixture.
- Integration test: `GET /api/v1/sessions/{id}/verification` returns a valid report for a session with completed test results.
- Integration test: Report contains `unresolved_risks` for any `inferred` edge node with `no_test` status.
- Integration test: PR summary contains the change description provided in the ImpactScope run.
